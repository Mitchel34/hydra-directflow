# Real-batch local throughput benchmark

The next timing campaign uses actual August 2023 inputs for gauge `03161000`, L168 and H18. The sealed fixture must contain all 744 hourly origins once, with separate `PRIMARY_APPROVED_A_OPTIONAL_R_V1` input and target quality policies. This is the complete selected-gauge engineering cohort; it does not decide the study's missingness or scientific selection policy. Fixed unit mappings are reused, with no fitted scaler.

The chronological boundary is August 25 at 00Z. Training labels must remain strictly before that boundary. This gives 558 training cases, 168 later validation cases and 18 purged origins. All cases in each batch are distinct; repeated passes through the fixed real cohort are explicit. Targets never enter model forward arguments. This benchmark discards losses and predictions and must not select scientific model weights or forecast skill.

Four architectures × CPU/MPS × batch sizes 16/32/64 gives 24 cases. Each gets five warmup plus 20 measured updates: **120 warmup +480 measured =600 total optimizer updates**. All 600 are precharged before the first worker. Failed and unstarted allowances remain charged; the script provides no automatic retry or budget increase. Workers execute sequentially with a 900-second campaign wall limit, four-GiB combined supervisor/worker RSS plus sampled MPS driver bound, and a two-GiB MPS driver allocation fraction. MPS unavailability fails without a substitute device.

`scripts/benchmark_real_batches.py --receipt <private-receipt.json>` prints the plan without running models. Execution additionally requires `--execute`, `--fixture`, a new ignored `--run-directory`, a new portable `--report`, and the exact `--approved-plan-sha256`. Complete fixture admission occurs before optimizer precharge. The root supervisor owns execution; unit tests use synthetic arrays and perform zero optimizer updates.

The fixture receipt uses `hydra-real-batch-fixture/v1`, with NPZ SHA/byte identity, gauge, history/horizons, independent quality-policy names, source and array digests, and source receipts. The NPZ contains the eight model value/mask arrays plus site/origin/history/target clocks, case IDs and weather source-cycle IDs; an optional soil-cycle array strengthens soil-age validation. Every coordinate, the exact chronological calendar, source availability, original masks and admitted finite values are checked. Values remain physical units until the declared fixed mapping.

Each fresh worker records environment/package versions, model parameter count, fixture/case/specification hashes, actual sample visits and unique-case counts. Timings cover fixture authentication, fixed mapping/tensorization, model setup, CPU gather/device copy, optimizer updates, validation, inference returning predictions to CPU, and checkpoint write/read/forward replay. Update timing includes finite loss/gradient/parameter checks; resource checks bracket each timed stage. First training-use and first eval-mode costs remain visible alongside 20 warmed samples and empirical median/p95. No OS or Metal cache flushing is claimed.

Validation uses 20 timed batches after one first-eval measurement. Inference uses 20 batches with no target arguments. Those passes have zero optimizer updates. Checkpoint weights remain private and are used only to verify exact eval-mode forward replay; this does not claim resumed-optimizer equivalence or authorize scientific use. Worker networking is denied and model dependency downloads are disabled.

`project_runtime` accepts explicit training/validation counts, epochs/trials/seeds, the count-audit SHA and its coverage qualification. It uses the measured common batch geometry, charges partial final batches as full batches, and includes positive first-use excess once per fit. Counts from a USGS-only audit must remain labeled as conditional on unresolved HRRR support. Full-corpus I/O/materialization, convergence, restart overhead and cloud hardware/cost are excluded. The projection is a scenario, not a scientific epoch choice or spending approval.
