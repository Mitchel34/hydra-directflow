# Resumable local preprocessing stores

`build_cached_development` accepts the same local source arguments as `build_multicycle_development`, plus `cache_directory` and optional `repair_corrupt=False`. Its arrays follow the existing assembly contract. Keep the cache under ignored `.cache/` or `.local/`; it contains source-derived values and private provenance and must not be pushed to GitHub.

For several bounded chunks, use `CachedDevelopmentSession` as a context manager. Supply the full local candidate inventory, qualified index, weights, USGS month map, USGS manifest and cache directory at construction. Then call `session.build(origins_utc=..., history_hours=168, archive_cycle_ids=...)` for each chunk. The session authenticates the sealed index, weights and source manifest at entry. It retains only verified basin reductions and monthly hourly observations in memory. Each build still enforces the existing 32-cycle/128-origin bounds and development/protected-assessment rules. A session admits at most 1,024 supplied cycle identities.

Every cycle entry binds the sealed-index hash and exact row digest, candidate-weight identity, relevant implementation hashes and development policies. It stores basin means, explicit masks and coverage plus the original record/field/availability dictionaries once. The 957-cell source arrays are discarded after authenticated reduction. Source hash checks and numerical/grid checks occur on a miss; verified cache hits do not reread or re-decode raw source payloads. Historical provenance remains attached to the stored source receipt.

Every USGS entry binds the original manifest and partition hash/size plus code/policy identities. It stores a complete pre-assessment month on an exact UTC-hour axis. Row presence and numeric validity are separate masks; missing values remain missing. Original qualifiers and source IDs use dictionaries shared across hourly rows. Chronological history/target windows are reconstructed from these stores without repeating original metadata for each forecast case. Full-month stores that would decode protected assessment values are refused.

Keys derive from source/code/policy identities. Compressed arrays and metadata have filenames equal to their content hashes. `COMMIT.json` binds identities, shapes, dtypes, byte counts and hashes. All files are flushed, then the staging directory is atomically renamed into `entries/`. An interruption leaves either a complete entry or an uncommitted staging directory. The latter is ignored on resume and retained as evidence; completed entries are reused after byte and semantic validation. A nonblocking process lock prevents concurrent writers. An unrelated nonempty directory, symlink payload, dataless file, unexpected member or oversized payload is rejected.

Corrupt committed entries fail closed. Explicit `repair_corrupt=True` moves the entry to `quarantine/` under the writer lock and reconstructs it from authenticated local sources. It preserves the damaged bytes and never rewrites source archives, original manifests or quality flags. No automatic cleanup deletes staging or quarantine evidence.

Receipts distinguish disk hits, new builds, explicit repairs and same-session memory hits, with per-chunk and cumulative counters, source/cache keys and stage timings. The session initialization time is reported separately so a monthly runner can charge the sealed-index pass once. These stores prepare development inputs; they do not freeze the scientific method, train models, access cloud resources or establish forecast skill.
