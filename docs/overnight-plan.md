# Connection-window work plan

This execution window starts with roughly eight hours of reliable Wi-Fi. Prepare
the code and dependencies needed for useful offline work, and push verified small
chunks to the public repository as they complete.

1. **Repository foundation.** Portable installable package, study boundary,
   source-code lineage, publication check and a clear work ledger.
2. **Protocol reconciliation.** Complete single-run weather selection, lagged
   history, independent soil state, H18 final label tail and protected scoring gate.
3. **Local source smoke.** Hash-check a retained development HRRR bundle, USGS
   monthly partition and existing weights. Produce one H18 input/target fixture
   with masks and aggregate evidence. Retain raw material outside Git.
4. **Four-model qualification.** Pin and cache dependencies while online. Check
   initialized Mamba2 and the other models on CPU/MPS, including checkpoint replay.
5. **Run instrumentation.** Local structured events, stage timings, finite metrics,
   immutable artifact hashes and explicit terminal state; export Prometheus text.
6. **Offline continuation.** Preserve the exact environments, wheel inventory,
   private fixture locations and commands. Any local real-data training probe is
   bounded and reported as engineering qualification, never forecast skill.

Each chunk needs its own tests/receipt and commit before publication. Raw data,
weights/checkpoints, source ledgers, credentials and private machine configuration
stay outside Git. Existing acquisition artifacts are read-only and do not need
to be restarted.

No paid cloud resources or SaaS account is selected. A cloud budget remains a
later decision based on measured end-to-end workflow time. Full scientific fits
and protected assessment require the remaining method choices to be frozen.

For travel, completed local artifacts should support qualification, code edits
and small development checks offline. `pip --no-index` resolution against the
wheel cache verifies dependency availability for its recorded platform only;
it does not prove Linux/CUDA readiness.
